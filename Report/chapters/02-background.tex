\subsection{System Architecture}
\subsubsection{Monolithic Architecture}

Monolithic architecture refers to a traditional software design pattern in which all components of an application --- including user interface, business logic, and data access layers --- are packaged and deployed as a single (Figure~\ref{fig:monolithic-architecture}), unified unit. In this model, the application runs as one process, often supported by a single codebase and a centralized database. \cite{thalor2024monolithic} describe monolithic systems as tightly coupled, meaning that changes in one part of the application often necessitate redeployment of the entire system.

The primary advantage of monolithic architecture lies in its simplicity. It is straightforward to develop, test, and deploy, making it particularly suitable for small teams and minimum viable products (MVPs). Since all components share the same memory space and runtime environment, monolithic applications also benefit from reduced communication overhead compared to distributed systems. This architecture enables rapid iteration during early development phases, where time-to-market and cost efficiency are prioritized.

\subsubsection{Domain Driven Design (DDD)}

Domain-Driven Design (DDD) is a software engineering methodology that integrates software architecture with the business domain to address the complexity of large-scale systems. Its primary objective is to ensure that software models accurately represent business processes, thereby shifting development from a technology-oriented to a domain-oriented perspective. \cite{ozkan2025ddd}

Two foundational concepts define DDD: Ubiquitous Language and Bounded Contexts. Ubiquitous Language is a collaboratively developed vocabulary shared between developers and domain experts. By embedding this language directly into communication and source code, DDD eliminates ambiguity and strengthens the alignment between the software model and the business domain. Bounded Contexts, in contrast, establish explicit boundaries around sub-domains, each maintaining its own model and terminology. This separation reduces complexity, prevents inconsistencies, and allows development teams to focus on smaller, coherent parts of the system.

Beyond conceptual clarity, DDD offers practical architectural benefits. The separation provided by Bounded Contexts naturally aligns with modern distributed paradigms such as microservices, where autonomous and loosely coupled services are essential. This approach enables systems to evolve alongside changing business requirements while maintaining technical robustness and strategic alignment with organizational goals. \cite{ozkan2025ddd}

\subsubsection{System Context Diagram}

The System Context Diagram is rooted in Structured Analysis and Design Technique (SADT). This methodology, developed in the 1970s, aimed to create a more disciplined approach to software development. The SCD is an integral part of Data Flow Diagrams (DFDs), where it serves as the top-level, or Level 0, diagram. \cite{paloalto2025dfd}

The theoretical underpinning is that by defining the system's boundaries and external interfaces first, developers can avoid getting bogged down in internal details too early. This aligns with the principle of separation of concerns, which advocates for breaking down a complex problem into smaller, more manageable parts. By isolating the system from its environment, the SCD allows for a clear focus on the system's external behavior before delving into its internal structure. This top-down approach ensures that the system being developed is relevant and responsive to the needs of its users and the environment it operates in.

\subsubsection{Codebase Structure}

A monorepo \cite{fernandez2024monorepo} is a single, unified version-controlled repository that houses a collection of logically distinct projects. This architectural paradigm contrasts with the traditional multirepo approach, where each project resides in its own separate repository. The primary advantage of a monorepo is the simplification of dependency management and a streamlined approach to code sharing across different applications, such as a web frontend and its corresponding API.

To address the performance challenges inherent in a large monorepo, namely slow build and testing times, the build system Turborepo \cite{turborepo2025intro} is employed. Turborepo operates on two key principles: content-addressable caching and parallel task execution. Content-addressable caching ensures that if the input to a build task has not changed, the build output can be instantly retrieved from a cache, eliminating redundant computation. Parallel task execution, in turn, leverages the inherent dependencies between projects to run independent tasks concurrently, maximizing the utilization of computational resources.

\subsection{Software Frameworks and Libraries}
\subsubsection{T3 Turbo Stack}
The T3 Turbo Stack \cite{t3app2025intro} is a modern full-stack development framework that unifies web development workflows by combining several powerful, opinionated tools into a cohesive environment. It provides a foundation that emphasizes type safety, developer productivity, and scalability. This stack serves as a model for efficient development workflows in contemporary software engineering. For a more comprehensive understanding of the T3 architecture, please refer to Figure~\ref{fig:t3-turbo-stack}.

\textbf{Core Components of the T3 Stack}
\begin{itemize}
  \item \textbf{Next.js:} A React framework for building fast, performant frontends. It handles complex setup like server-side rendering, routing, and API routes from a single codebase.
  \item \textbf{tRPC:} This library enables type-safe API communication between your client and server. It allows you to call backend functions directly from your frontend code, automatically inferring types. According to Vercel's documentation, this approach ``reduces the likelihood of integration errors while also ensuring maintainability across large applications.''
  \item \textbf{Tailwind CSS:} A ``utility-first'' CSS framework that lets developers build custom designs by composing pre-defined utility classes directly in their HTML.
  \item \textbf{Prisma:} An open-source database toolkit that provides a type-safe and intuitive way to interact with your database.
\end{itemize}

\thesisfigure{ch2-T3-turbo-stack.png}{T3 Application Architecture Overview}{T3 Application Architecture Overview}{hxann2025t3architecture}{t3-turbo-stack}

\textbf{Why the T3 Stack Matters}

The T3 Stack’s significance lies in its powerful combination of tools, which addresses common challenges in full-stack development. Its emphasis on type safety is a game-changer for mitigating runtime errors. By sharing types across the entire stack --- from the database (Prisma) to the API (tRPC) and the UI (Next.js with TypeScript) --- it prevents bugs that often arise from mismatched data.
Furthermore, the stack’s ``convention over configuration’’ philosophy greatly enhances developer productivity, allowing for quicker iteration and more efficient development. This streamlined workflow ensures that as an application scales, it remains highly maintainable and easier for new team members to work on.

\subsubsection{MedusaJS}
\thesisfigure{ch2-medusa-js.png}{Medusa Dashboard}{Medusa Dashboard}{medusajsdashboard}{medusa-dashboard}

MedusaJS is an open-source, headless e-commerce framework that emphasizes flexibility and modularity in backend commerce logic. As a headless system, it decouples the backend services from the user-facing presentation layer (Figure~\ref{fig:medusa-dashboard}), which allows for greater system adaptability in multi-channel environments. Unlike traditional monolithic e-commerce platforms, MedusaJS enables developers to build marketplaces, subscription systems, and online storefronts through a customizable plugin-based architecture. This modular nature aligns with the principles of service-oriented architecture, making it suitable for projects that anticipate evolving requirements and third-party integrations. \cite{medusa2025platform} Furthermore, MedusaJS aligns with modern trends in digital commerce, where organizations increasingly adopt open-source frameworks to maintain greater control over customization and reduce dependency on proprietary solutions.

\subsubsection{Next.js}
Next.js \cite{nextjs2025docs} is a React-based framework that extends the capabilities of traditional single-page applications by offering server-side rendering (SSR) and static site generation (SSG). These rendering modes allow developers to improve application performance and search engine optimization while reducing time-to-first-byte (TTFB) for users. Next.js’s App Router paradigm introduces nested layouts and modular directories, streamlining the development of scalable and maintainable applications. 

From a business perspective, the performance enhancements of Next.js translate into significant improvements in key business metrics. Case studies have demonstrated that faster page load times lead to a reduction in bounce rates and an increase in conversion rates, with one e-commerce study reporting a 20\% increase in mobile conversions following a migration to Next.js \cite{shah2025nextjs}.

\subsubsection{React Native}
React Native is an open-source framework that allows developers to build mobile applications for iOS and Android using a single codebase of JavaScript and React. This approach differs from traditional native development, where separate codebases are maintained for each platform. At its core, React Native translates the JavaScript code into platform-specific UI components, providing a user experience that is visually and functionally indistinguishable from a native application. The framework's ability to reuse code across different operating systems streamlines the development process while retaining access to native APIs for performance-critical functions. It has gained widespread adoption due to its ability to offer a unified development experience and a rich ecosystem for creating high-quality mobile applications. \cite{reactnative2025intro}

\subsubsection{Expo}
Expo is a development framework built on top of React Native that simplifies mobile application development. It provides a managed workflow with pre-configured tools, over-the-air (OTA) updates, and access to a wide range of native APIs, which enables developers to rapidly prototype and deploy applications. Expo’s approach lowers the barrier to entry for mobile development by abstracting away complex native setup processes, allowing teams to focus on the application logic. The framework is particularly valuable for accelerating the delivery of Minimum Viable Products (MVPs) and streamlining app lifecycle management, despite potential limitations in its managed environment for applications requiring advanced native modules. \cite{expo2024coreconcepts}

\subsubsection{tRPC}
tRPC is a framework designed for building fully type-safe APIs in TypeScript applications\cite{trpc2025quickstart}. Its core innovation lies in its ability to eliminate the need for traditional API schema definitions, such as those used in REST or GraphQL, by sharing type definitions directly between the client and the server. This architectural approach ensures end-to-end type safety, which effectively mitigates common runtime errors associated with data contract mismatches and streamlines the maintenance of both frontend and backend systems. By providing developers with real-time autocompletion and compile-time error checking, tRPC significantly enhances the developer experience and accelerates the development cycle. This provides a lightweight and strongly typed communication layer that exemplifies a growing trend in modern full-stack development, prioritizing efficiency, developer experience, and system reliability. \subsection{Programming Languages}
\subsubsection{TypeScript}
TypeScript \cite{appiness2025typescript} is an open-source programming language developed by Microsoft that builds upon JavaScript by adding static typing, interfaces, and other advanced language features. As a syntactic superset of JavaScript, TypeScript allows developers to write type-safe code while remaining compatible with existing JavaScript projects. Introduced in 2012, it is widely adopted for developing large-scale and maintainable applications, particularly in enterprise and team-based environments. TypeScript enhances code quality, readability, and developer productivity by enabling early detection of errors, strong tooling support, and improved maintainability in complex software systems.

\subsection{Database \& Data Management}
\subsubsection{Supabase}
Supabase is an open-source Backend-as-a-Service (BaaS) platform that provides developers with managed PostgreSQL databases, authentication services, real-time APIs, and edge functions \cite{supabase2025architecture}. As a BaaS solution, it abstracts much of the complexity of backend development, enabling rapid prototyping and scalable application deployment without extensive server-side configuration. Supabase emphasizes developer productivity by offering features such as instant database provisioning, real-time data synchronization, and seamless integration with modern web and mobile frameworks. Its open-source nature distinguishes it from proprietary BaaS providers, fostering transparency, community-driven innovation, and flexibility in system design. 

\subsubsection{Drizzle ORM}
Drizzle ORM \cite{drizzle2025overview} is a TypeScript-first Object-Relational Mapping (ORM) library specifically designed for relational databases. It fundamentally differs from many traditional ORMs by adopting a schema-first approach, where the database schema is defined directly within the application's code using a strongly typed API. This methodology provides developers with compile-time error checking, which significantly enhances code safety and maintainability by identifying data-related errors before the application is even executed. By providing a type-safe query builder, Drizzle ORM reduces the likelihood of runtime errors, thereby improving developer productivity and establishing a robust, predictable interface between the application and the database. This approach aligns with modern software development paradigms that prioritize static typing and early error detection to build more reliable and scalable systems.

\subsubsection{PGVector}
\thesisfigure{ch2-PGVector.png}{Overview Diagram of PGVector implementation}{Overview Diagram of PGVector implementation}{pgedge2025pgvector}{pgvector-diagram}
PGVector is an open-source extension for PostgreSQL that enables vector similarity search within relational databases \cite{supabase2025pgvector}. It supports the storage and retrieval of high-dimensional vector embeddings, making it suitable for artificial intelligence and machine learning applications such as semantic search, recommendation systems, and natural language processing. By integrating vector-based queries directly into PostgreSQL (Figure~\ref{fig:pgvector-diagram}), PGVector allows developers to combine the robustness of relational databases with the flexibility of modern AI-driven search capabilities. In platforms such as Supabase, PGVector extends traditional database functionality to support efficient embedding-based search across large datasets.

\subsubsection{Apple Developer Account}
The Apple Developer Account is an essential program offered by Apple that provides developers with the resources, tools, and certifications necessary to build, test, and distribute applications across Apple’s ecosystem, which includes iOS, iPadOS, macOS, watchOS, and tvOS. Enrollment in the program grants access to development kits such as Xcode, official documentation, and platform-specific APIs, which collectively streamline the process of application development. \cite{apple2025devdocs}

\subsection{Development Tools}
\subsubsection{Turborepo}
Turborepo is a high-performance build system specifically designed for managing a monorepo \cite{turborepo2025intro}, which is a version-controlled repository containing multiple distinct projects. Its core function is to optimize build times by leveraging a sophisticated cache system that only executes tasks on code that has changed. This approach prevents redundant computation and enables the parallel execution of dependent tasks across the entire repository. The result is a significant improvement in development velocity, as developers can work on individual projects while ensuring that the entire codebase remains consistent and up-to-date with minimal overhead.

\subsubsection{ESLint \& Prettier}
ESLint  and Prettier are a complementary pair of tools used to enforce code quality and stylistic consistency. ESLint is a static code analysis tool that programmatically evaluates JavaScript and TypeScript code to identify and report on issues that may compromise code quality, ranging from syntax errors to violations of predefined coding standards \cite{eslint2025gettingstarted}. Prettier, on the other hand, is an opinionated code formatter that automatically restructures source code to a uniform style, eliminating the need for manual formatting and preventing style-related debates within a team \cite{prettier2025docs}. By integrating these tools into the development workflow, the team ensures a standardized, readable, and maintainable codebase.

\subsubsection{Git \& Husky}
Git is a distributed version control system (VCS) that serves as the foundation for modern collaborative software development. Its primary function is to track and manage changes to source code over time, enabling multiple developers to work on a project simultaneously without compromising code integrity \cite{git2025docs}. The distributed nature of Git ensures that every developer maintains a complete, local copy of the project's history, which facilitates robust, conflict-resilient branching and merging workflows. This architecture is crucial for parallel development and ensures the project's history is resilient.
To further enforce a structured development process, the project leverages Husky \cite{husky2025docs}, a tool that simplifies the implementation of Git hooks. Git hooks are custom scripts that are triggered automatically at key points in the Git workflow, such as before a `commit` or a `push`. Husky acts as an automated quality gate, ensuring that essential checks such as running linters and tests are performed on every code change. This practice prevents the integration of substandard or non-compliant code into the shared repository, thereby upholding code quality and consistency throughout the entire development lifecycle.


\subsubsection{Docker}
Docker is an open-source containerization platform that enables developers to package applications and their dependencies into lightweight, portable containers \cite{docker2025overview}. Containers ensure environment consistency, allowing applications to run reliably across different systems without conflicts. 

Docker supports efficient resource utilization, rapid deployment, and scalability, making it a core technology in modern DevOps practices and cloud-native development. Its integration with orchestration tools such as Kubernetes further enhances its role in building and managing distributed applications.
